## G4.2 — Routing-state inventory and truth points

Execution was traced in source, synchronous and streaming, legacy and governed. The decision facts become true at
these points, and only these:

| Fact | Truth point (source) | What it proves |
|---|---|---|
| CANDIDATE UNIVERSE | `ProviderExecutionCoordinator.governedCandidateSet` (`:337-414`), `routeRequest`/`resolvedRoutes` (`:157`, `:291-315`) | Which routes configuration proposes. **Not** authorization, **not** selection. |
| AUTHORIZED ENVELOPE | `CandidateAuthorization.authorizedSet` (`:383-396`) over `ProviderInputRelease` (`:351-353`), after `WorkloadGovernanceResolver.resolve` (`:359-367`) | Which routes governance permits for this workload. A refused workload throws before any provider is reached (`:365-367`). |
| VIABLE ENVELOPE | `CandidateViability` probe over `circuitBreaker.openUntilMillis` (`:400-407`) | Which authorized routes can execute now. Availability is **observed, never consumed** (`:398-399`). |
| SELECTED | `CandidateSelection.select(...)` (`:192`) → the `Selected` branch (`:197-214`) → **`request.beforeRoute.beforeRoute()` (`:216`)** → dispatch (`:217-219`). Legacy path: same gate at `:266`. | The route the execution machinery will dispatch. Reached only after circuit-breaker admission (`:200`). |
| CIRCUIT-BREAKER REFUSAL | `CircuitBreakerAdmission.Rejected` (`:201-213`), announced through `walk.transition(..., CIRCUIT_BREAKER_OPEN, ...)` (`:205-211`) | An admitted candidate was refused by availability, and the walk moved. |
| FALLBACK | `ProviderFallbackGate.transition(ProviderFallbackTransition)` — `GovernedCandidateWalk.transition` (`:569-592`), called from `:205`, `:446`, `:507`; legacy `:260`, `:276`; streaming `StreamingRouteAttempts.kt:176`, `:261`, `:288` | Execution **moved** from one route to another, with the reason. The gate is invoked only when `next != null` (`:576`) — a configured route that was never reached produces no transition. |
| BLOCKED / TERMINAL REFUSAL | `GovernedCandidateWalk.failExhausted` → `exhausted(...)` (`:533-567`, `:541-567`); legacy tail (`:285-288`) | No candidate remains selectable. `exhausted()` distinguishes `nothingAuthorized` (non-retryable) from `NO_VIABLE_CANDIDATES` from other `SelectionRefusal`s. |
| DISPATCH (not selection) | `ProviderAttemptExecutor.startAttempt` (`:111-135`) → `beforeProviderInvocation` (`:58`) → `callOnce` (`:59`) | Which provider/model an **attempt** is being made against. Retries re-enter here for the same route, so this is not a per-selection signal. |

**Conflations that must not be made**, and the source that makes each one unsafe:

- **Selection is not candidate listing.** `resolveCandidates` proposes (`ProviderRoutingPlan`); only the `Selected`
  branch after authorization, viability and admission is a selection.
- **Selection is not completion.** `beforeRoute` runs before dispatch (`:216-219`). A `SELECTED` record cannot attest a
  response.
- **`routeIndex > 0` is not fallback.** It is `resolvedRoutes.indexOf(route)` (`:218`); the governed walk narrows the
  envelope and can announce exclusions *before* the continuation candidate (`announceAvailabilityTransitions`,
  `:426-455`), so a run can start at index > 0 without any fallback transition.
- **An exception is not BLOCKED.** `error.rethrowIfCancellation()` (`:221`, `:269`) exits on cancellation;
  `fallbackPolicy.decide` classifies only `CircuitBreakerOpenException`, `TimeoutException` and retryable
  `ProviderException` as continuation (`ProviderFallbackPolicy.kt:15-21`) and `DlpInspectionException` as Stop.
  Post-dispatch transport failures are provider outcomes, not routing refusals.

## Why not Path A

A live producer is achievable in principle — the three truth points exist and the fallback gate already carries
previous/next route, reason, correlation id and security context. It is not a **narrow** change, and each blocker below
is a stop condition from the task, not a judgement call:

1. **There is no production-accessible capture path for runtime evidence — for any family.** No collector, sink or
   registry exists in any `src/main`; `RuntimeEvidenceBundleWriter` is invoked only from tests and the example path
   (G4.1). Wiring `provider.route` alone would mean inventing an engine-side capture architecture that the policy,
   approval and tool.permission families do not have, i.e. a new lifecycle for one family — the mission's
   "creating a new public lifecycle or persistence architecture".
2. **The truth points are `internal`.** `ProviderRouteGate`, `ProviderFallbackGate` and `ProviderResolutionGate` are
   `internal fun interface`s in `tramai-engine`, so no application can supply an observing implementation. Reaching them
   from outside needs new public API on a module that ships an `.api` dump, plus API-compatibility review.
3. **The engine already declares route selection not evidence-eligible.** `tramai.route.selected` exists and is
   deliberately `auditEligible = false, evidenceEligible = false` (`RuntimeEventCatalogue.kt:312-326`). Building a
   producer on it would require either flipping an established evidence-eligibility decision or reconstructing
   decisions from attempt events — the reconstruction the task forbids ("capture the facts at the point where they
   become true").
4. **The existing observer signal is insufficient by construction.** `IS_FALLBACK = routeIndex > 0` is index-derived;
   the mission states explicitly that this is not proof of a fallback transition. Consuming it would ship a producer
   that mis-reports fallback and blocked decisions.
5. **Observation inside the routing walk has no established delivery policy.** The walk is fail-closed: an observer that
   throws inside `beforeRoute` or `transition` lands in the retry/fallback path (`:220-237`, `:588-591`). The mission
   forbids inventing a fail-closed policy by analogy, and none is established for in-loop evidence delivery.
6. **Coverage would be partial at best, and the task requires saying so.** Synchronous governed, synchronous legacy and
   streaming selection are three different code paths (`ProviderExecutionCoordinator:173-175`, streaming
   `StreamingRouteAttempts`/`StreamingGovernedWalk`), and the refusal vocabulary is collapsed in `exhausted()`
   (`:541-567`) so per-cause `BLOCKED` reasons are not recoverable there without touching the refusal path.

None of this weakens provider governance; it is the reason the contract is being declared rather than faked. Per the
roadmap, either outcome is permitted — and **Path B is not a claim that the family works in production.**

## Exact contract semantics (G4.4 preserved)

Unchanged, and now stated normatively in the export model:

- `runtime-evidence.v1`, `eventType = "provider.route"`, `source.component = "provider-router"`.
- `decision.kind` ∈ `SELECTED`, `FALLBACK`, `BLOCKED`; reason codes limited to the six allowlisted values
  (`ProviderRoutingRuntimeEvidenceExporter.kt:45-52`), unknown codes normalised to the generic constant.
- No raw provider names, model names, prompts, credentials or tool arguments — digests only (`:121-132`), and both
  subject and payload digests keep their existing SHA-256 semantics (`:139-166`).
- `SELECTED` attests a routing decision, never a returned response. `FALLBACK` attests an actual or authorized move,
  never a configured route order. `BLOCKED` attests a routing-authority refusal, never an arbitrary exception.
- G1–G3 limitations are preserved: no new authority is created from an observer event, and the
  authorization-vs-completion and enforcement-strength limitations are untouched.

## Remaining gap and follow-up task

The wiring work is specified as its own task record: **[TASK-0.7.4b7 — Wire a live `provider.route` producer](TASK-0.7.4b7-PROVIDER-ROUTE-LIVE-PRODUCER.md)**
(not part of 0.7.4b, not a prerequisite for the schema freeze). It names the truth points with file:line, the seven
blockers listed under [Why not Path A](#why-not-path-a), the required discriminators, and the acceptance criteria. Summary of scope:

1. Choose the capture surface deliberately: an engine-owned, bounded, opt-in evidence sink with an explicit delivery
   policy, or an application-supplied source that the engine fills. Do not add a public API without API-compatibility
   review, and do not make evidence delivery part of routing control (a throwing producer must not change routing).
2. Emit `SELECTED` at `ProviderExecutionCoordinator:216` / `:266` (governed and legacy), carrying route identity, run
   identity where available, correlation id, and attempt or selection identity that survives retries.
3. Emit `FALLBACK` from the fallback gate (`:569-592` and the streaming sites), using the reason the policy supplied —
   never from `routeIndex`.
4. Classify `BLOCKED` where the refusal is produced (`exhausted`, `:541-567`), mapping `nothingAuthorized`,
   `model-registry`/capability refusal, `NO_VIABLE_CANDIDATES` and circuit-breaker exhaustion separately; never
   fabricate it from cancellation or post-dispatch failure.
5. Carry run identity into the fallback transition carrier (`ProviderFallbackTransition`, `:99-106`), which today
   carries correlation but not the governed run identity.
6. Cover the streaming path or state the uncovered paths explicitly in the same PR.
7. Required tests: real-machinery discriminators that fail when the emission is removed, when it moves before the
   authoritative decision, and when it fires on an invalid transition; plus a check that behaviour is unchanged when
   capture is disabled or the sink is unavailable.
