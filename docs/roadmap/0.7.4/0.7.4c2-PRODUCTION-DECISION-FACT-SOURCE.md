# 0.7.4c2 — Production governance decision fact source

Status: **CONTRACT QUALIFIED — IMPLEMENTATION BLOCKED** (owner decision required before code).
Base: `release/0.7.0` = `ce503dda0e68da4ba294538aa44b5afb19b7ae10` (#531).

This PR contains the C2.1 coverage contract and the evidence for a blocker discovered before any
code was written. **No production code, no gate, no baseline, no module boundary, no schema and no
public API is changed here.** The blocker is an enforced architectural rule, not a missing design.

## 1. What was established, and what stopped the implementation

C2.1 is complete: the audit store's real guarantees, the run-to-stream association rules, the
attested-range basis, the family partitioning and the bundle limitations are recorded below from the
code that implements them.

C2.2 cannot be implemented in this repository as it stands. `GovernanceDecisionFactSource` is
`internal` to `:tramai-control-plane`, so **only** that module can implement it; and
`:tramai-control-plane` is **forbidden** from depending on `:tramai-security`, where `AuditStore`
lives. The refusal is machine-enforced and reproduced below with a matched pristine control.

## 2. C2.1 — Coverage contract

### 2.1 What the audit store itself owns

Verified against `AuditStore`, `AuditEvent`, `InMemoryAuditStore`, `FileAuditStore`,
`JdbcAuditStore` and `AuditStoreTck` at the base SHA.

| Fact | Owner | What makes it source-owned |
|---|---|---|
| `sequenceNumber` | the store/stream | contiguous per stream, first event `1`, each append must equal `latest + 1` (`audit-sequence-gap`); TCK asserts `first event has sequence 1`, `second event has sequence 2` |
| `auditStreamId` | the emitter, validated by the store | append rejects a mismatching id (`audit-stream-id-mismatch`) |
| `eventId` | the emitter, validated by the store | non-blank, unique per stream (`audit-duplicate-event-id`) |
| `previousEventHash` / `eventHash` | the emitter, recomputed by the store | must equal `latest.eventHash` (`audit-hash-chain-broken`) and the event's own recomputed hash (`audit-event-hash-mismatch`) |
| `schemaVersion` | the store contract | must equal `CURRENT_AUDIT_SCHEMA_VERSION` |
| `workflowRunId`, `correlationId`, `actor`, `policyVersion`, `workflowDigest`, `reasonCode` | the emitter | carried per event, all **nullable** |
| `metadata` | the emitter, allowlisted | bounded, safe-key filtered at the emitter and again at the exporter |

The store validates and preserves; it does not enrich. It has no notion of a run, a family or a
decision — those are interpretation, and belong to the consumer.

### 2.2 Run-to-stream association

`AuditStreamIdResolver.resolve(PolicyContext)` returns `workflowRunId` when that is non-blank,
otherwise `correlationId`, and throws when neither is usable. The resolver is an interface and is
customised by callers. Two consequences bind any run-scoped read:

1. `auditStreamId == workflowRunId` is the **default resolver's behaviour**, not a property of the
   store. A source that assumes it is wrong for any deployment using a custom resolver.
2. `AuditEvent.workflowRunId` is nullable and per event. Attribution must therefore be established
   from the event, and a record whose own run does not match the requested run must be refused
   rather than folded into the projection.

### 2.3 What qualifies as an attested read range

A defensible range needs three things, and only the first is available unconditionally:

- **source-owned positions** — `sequenceNumber`, contiguous from 1 per stream. VERIFIED.
- **a bounded, identifiable snapshot** — available only in a specific read shape. `InMemoryAuditStore`
  serialises appends and reads under one per-stream lock, so a full read is a consistent view of
  that stream. `FileAuditStore` documents the opposite: "Read operations do not acquire locks", and
  appends are serialised separately. `AuditStore`'s default `readStreamPage` filters a full
  `readStream` result, and `JdbcAuditStore` reads with its own `ORDER BY sequence_number` query
  outside the `SELECT ... FOR UPDATE` append transaction. **A page boundary is therefore not a
  snapshot and cannot, by itself, justify `COMPLETE`.**
- **integrity verification** — `AuditChainVerifier.verify(events)` proves the *internal* consistency
  of the list it is handed: homogeneous stream id, schema version, hash algorithm, unique event ids,
  chain position (`previousEventHash` linkage and sequence contiguity) and each event's recomputed
  hash. It proves nothing about completeness: a prefix of a stream verifies cleanly, and `verify`
  returns `isValid = true` for an **empty** list, which must never be read as "no decisions
  occurred".

The strongest range this SP offers without new semantics is therefore: *read the stream from
position 1 up to a named position, contiguously, and verify the chain over exactly that list; report
`COMPLETE` only for that verified prefix at that read, and `UNKNOWN` for anything the read cannot
attest.* A cursor-based page read alone yields a contiguous observed set inside an unverified range —
`GAPS_PRESENT`/`UNKNOWN`, not `COMPLETE`.

### 2.4 Which audit events are decision records

Family partitioning already exists and is reused rather than reinvented
(`PolicyDecisionRuntimeEvidenceExporter`, `ToolPermissionRuntimeEvidenceExporter`):

- **tool.permission** — `enforcementPoint` in `{BEFORE_TOOL_EXPOSURE, BEFORE_TOOL_EXECUTION,
  BEFORE_TOOL_RESULT_REINJECTION}` and `decision` in `{ALLOW, DENY, REQUIRE_APPROVAL}`; a recognised
  tool enforcement event without `metadata.toolName` fails closed.
- **policy.decision** — every other event whose `decision` is in `{ALLOW, DENY, REQUIRE_APPROVAL}`.
- **neither** — anything else in the same stream, including approval lifecycle events
  (`AuditEngineApprovalLifecycleAuditEmitter`), DLP redaction events
  (`AuditEngineDlpRedactionAuditEmitter`), sovereign-ops outbox traffic and any unrecognised
  enforcement point or decision token.

The consequence is a contract problem the task anticipated: a stream contains events outside both
families, so a family-filtered read is a **strict subset** of the stream. Claiming `COMPLETE` for the
stream from such a read overstates the source, and claiming it per family over per-stream positions
was already shown to be wrong in 0.7.4c1. Either the completeness claim stays `UNKNOWN`, or the
internal contract is corrected so that completeness is assessed over the *attested stream range* with
the family partition reported separately. That correction is a decision to take together with §3,
because it changes the same seam.

### 2.5 Evidence bundles (C2.4)

Inspected: `RuntimeEvidenceRecord`, `RuntimeEvidenceJsonlWriter`, `RuntimeEvidenceBundleWriter`,
`ManifestJsonReader`, `RuntimeEvidenceContractValidator`, `PolicyDecisionRuntimeEvidenceExporter`,
`ToolPermissionRuntimeEvidenceExporter`.

- `RuntimeEvidenceRecord` exposes **no** `sequenceNumber` — confirmed by reading the type.
- JSONL order is serialisation order of the list handed to the writer; it is not a source-owned
  order. Line numbers, timestamps, sorting and `eventId` are all non-attesting substitutes and are
  refused as bases for `sourceSequence`.
- The manifest describes the files the writer produced (names/digests/counts). File counts are not a
  coverage range.

**A bundle-backed source is therefore DEFERRED**, with these exact prerequisites before it can exist:
a source-owned ordering value carried into the frozen record (or a bundle-level attestation of the
range it was derived from), plus a bundle reader whose validation establishes that the file set it
read is the set the manifest attests. Neither exists today, and neither can be added without
changing the frozen public evidence contract. Per C2.4 this deferral does not block the audit-backed
path — it is recorded so parity is not manufactured.

### 2.6 Consumer inference per domain

| Domain | Audit store as a source | May infer | Must not infer |
|---|---|---|---|
| Run identity | `workflowRunId` per event (nullable) | a record belongs to the run it names | that a stream is a run |
| Policy decisions | yes, family `policy.decision` | authorization decision + reason code | execution, completion or success |
| Tool permissions | yes, family `tool.permission` | authorization at an enforcement point | that the tool ran or returned |
| Approvals | events exist, latest authoritative state is owned elsewhere | that an approval event occurred | that approval state is current |
| Provider routing | no producer in the stream | nothing | that absent routing means no routing |
| Execution outcomes | absent | nothing | completion from `ALLOW` |
| Boundary provenance | `enforcementPoint` is a declared label | the enforcement point that emitted | that the event originated from it |
| Lifecycle/control | owned by the registration authority, not the audit store | — | audit facts are current registration state |

## 3. The blocker, reproduced with a control

The constraint chain, each link verified independently:

1. `GovernanceDecisionFactSource` and every type in the 0.7.4c1 seam are `internal` to
   `:tramai-control-plane` (`GovernanceProjectionReader.kt:19`, `GovernanceProjection.kt`). Kotlin
   `internal` is compilation-unit scoped, so no other module can implement the port.
2. `:tramai-control-plane` must not depend on `:tramai-security` where `AuditStore` lives:
   `config/quality/module-catalog.yml` gives control-plane layer `core-contracts`, security layer
   `governance-security`, and `config/quality/module-boundaries.yml` declares the edge forbidden.
3. Making the port public to relocate the adapter is excluded: C2 non-goals forbid new public API,
   and the port's input types (`RecordedDecision`, `DecisionFactRead`) are part of that surface.
4. Reading through a legally-placed bridge is excluded for the same reason: an out-of-module
   implementer cannot see an `internal` port, and a bridge the module cannot reference is not a
   bridge.

Decisive experiment — the edge added to a scratch tree, then reverted, with the **same task run at
the pristine base as control** (JDK 21; JDK 25 makes the ABI validator fail before the boundary
check runs):

| Run | `dependency-boundaries` | `api-architecture` |
|---|---|---|
| pristine base `ce503dda` (control) | **PASS** | FAIL — pre-existing, see below |
| same tree + `implementation(project(":tramai-security"))` | **FAIL** | FAIL — same diagnostic identity |

```
FORBIDDEN_LAYER_EDGE: Dependency policy violation: :tramai-control-plane may not depend on
  :tramai-security (governance-security)            [modulePath: :tramai-control-plane]
FORBIDDEN_LAYER_EDGE: Forbidden edge: :tramai-control-plane (core-contracts) ->
  :tramai-security (governance-security): Core contracts must not depend on governance-security
```

Unrelated pre-existing failure, recorded so it is not mistaken for this work: `api-architecture`
also fails at the pristine base, for `:tramai-control-plane`, `:tramai-persistence-jdbc` and
`:tramai-security`, with `API_COMPATIBILITY_FAILED` — "changed without an exact hash-bound migration
entry" plus one stale/orphaned migration entry for control-plane. Same diagnostic identity with and
without the scratch edge, so it is attributable to the base, not to the edge. **Not touched here.**

## 4. Options — owner decision required

| Option | What it costs | Risk |
|---|---|---|
| **A. Admit the edge** — add a `knownAllowedEdges` entry (or a layer-policy change) for `:tramai-control-plane -> :tramai-security`, keeping the adapter in the control plane | smallest change; the adapter can read `AuditStore` directly and stay `internal` | relaxes a deliberate boundary rule ("Core contracts must not depend on governance-security") to accommodate new work, which this repository forbids without evidence the rule is wrong |
| **B. Public seam** — make the decision-fact seam public so a layer-legal module can supply the audit-backed source | no boundary change; adapter sits in a module that already sees both | new public API + `.api` dump change, both explicit C2 non-goals; also exposes the authority model as a supported contract before its reader is production-backed |
| **C. Relocate the 0.7.4c1 projection contract** into a module whose layer may depend on `governance-security` (runtime-execution layer already may), keeping every type `internal` | no gate change, no public API change; the projection becomes legal to bind to the audit store | moves the read boundary out of the control plane and contradicts the 0.7.4c1 record and the roadmap narrative; larger than one focused slice |

Recommendation: **C if the boundary rule is treated as settled architecture, A only if the owner
rules that a read-only audit SPI edge is acceptable for the control plane**. B is the option I would
not take: it converts a deliberate internal seam into a supported public contract to solve a
placement problem, and the C2 brief excludes it.

Until one is chosen, the audit-backed implementation cannot be compiled, and reporting `PASS —
AUDIT-BACKED SOURCE VERIFIED` would be false.

## 5. Not done, and the next discriminating step

- No adapter, no range attestation implementation, no integration test: blocked per §3, not attempted
  with a workaround.
- No mocks substituted for the production read path (C2.5).
- No gate, boundary, baseline, deviation, workflow, schema or public API change.
- No bundle-backed source (C2.4 deferral with prerequisites named in §2.5).

Next step after the owner's decision, in order: (1) place the adapter legally; (2) implement the
range attestation of §2.3 — contiguous read from position 1 to a named position plus chain
verification over exactly that list — and decide the §2.4 completeness correction that goes with it;
(3) the real end-to-end path (emitter → `appendNext` → store → adapter → reader → projection) with
the real registration authority; (4) adversarial discriminators and mutation kills for range
attestation, run attribution and family partitioning/chain integrity.
