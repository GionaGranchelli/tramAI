### 6.2 The source

`AuditBackedGovernanceDecisionFactSource(auditStore, streamAssociation, pageSize, maxEventsPerRead)`
implements the frozen `GovernanceDecisionFactSource` seam:

- **Order** — `sourceSequence` is the store's own `sequenceNumber`. Nothing is derived from JSONL
  order, timestamps, line numbers or event-id sorting.
- **Attested range** — `assertedRange` is populated only when the read captured stream positions
  `1..head` contiguously, `AuditChainVerifier.verify` passed over exactly those events, **every read
  event carries the requested stream id**, the last event's position **and hash** equal the observed
  head's, and a second `latestEvent` read shows the head's position and hash unchanged. Positions
  alone are not enough: the verifier proves only that the returned list is internally consistent, so
  a source answering with a different but coherent chain of the same length would otherwise be
  attested. (Owner finding P1-B.) A bounded read returns the prefix it verified with **no** range; a
  read a concurrent append raced returns **no** range. The projection turns that into `UNKNOWN`,
  never `COMPLETE`.
- **Integrity** — a chain that does not verify throws `AuditDecisionIntegrityException` carrying the
  stream id. Unverified records are not a partial answer; the read fails.
- **Attribution fails closed** — a run-named stream that carries another run's event raises
  `AuditDecisionAttributionException` (stream, requested run, offending position). The event is
  **refused, not filtered**: this run's own decisions are in that stream and the read still fails,
  because returning them would present a mixed-run stream as a clean read. Multi-run streams are
  therefore unsupported by this source; a shared-stream mode would be a separate mode with its own
  attribution and completeness semantics. (Owner finding P1-A; the reader's own cross-run refusal
  remains as the second line of defence.)
- **Family recognition is an allowlist in both directions** — the decision token must be one of
  `{ALLOW, DENY, REQUIRE_APPROVAL}`, the enforcement point must be a known engine enforcement point,
  and a tool enforcement event without `metadata.toolName` is **not** a tool permission and does not
  fall back to policy. This is deliberately stricter than the existing exporters, whose policy family
  is defined by exclusion (see §2.4) — an event with an unrecognised enforcement point and an `ALLOW`
  token passes their filters and is refused here. A discriminator pins that divergence, asserting the
  exporter *does* export it while the source does not.
- **Untrusted persisted input** — the only metadata value read is the `toolName` qualifier; nothing
  else from `metadata` reaches the projection, and a reason code is carried only if it matches a
  bounded safe-token pattern, dropped otherwise, never replaced.
- **Boundary strength** — `DeclaredBoundary(id = enforcementPoint, registeredStrength = null)`: the
  label the record declares, at the strength audit data can prove, which is none.
- **Telemetry** — `telemetryFor` returns nothing. An audit stream is evidence, not observations.
- **Run-to-stream association** — supplied, never assumed: the store has no run index, so
  `RunStreamAssociation` is an explicit parameter whose default is the identity rule the default
  resolver happens to produce. Its limitation is stated where it is defined.

### 6.3 The end-to-end path demonstrated

`AuditEnginePolicyDecisionAuditEmitter` → `AuditEngine.emit` → `AuditStore.appendNext` in
`InMemoryAuditStore` (a real SPI implementation) → `AuditBackedGovernanceDecisionFactSource` →
`GovernanceProjectionReader` against the real `WorkloadRegistrationAuthority`. No mock stands at the
audit boundary. Asserted end to end: a persisted policy DENY and a policy ALLOW reach the policy
family with their source positions and the attested range; a tool permission decision reaches the tool
family and not the policy family; an `ALLOW` stays `POLICY_AUTHORIZATION_RECORD` and never
`AUTHORITATIVE_PERSISTED`; advancing registration state does not move the decision history; a bounded
read reports `UNKNOWN` completeness with no coverage; an empty read reports an unobserved family
rather than an absent producer; `provider.route` still reports `NOT_PRODUCED`.
