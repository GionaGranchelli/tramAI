# 0.7.4b2 / G1b — Governed Tool-Permission Evidence Attribution

Status: implemented, awaiting exact-head review.
Base: `067e6f61224f67c6b19c4da5c2f6826560450dc3` (`release/0.7.0` after 0.7.4b-CI-0001).

## Goal

Carry the governed identity that G1a introduced into the `tool.permission` evidence family, so that
the identity a tool decision was **evaluated under** is the identity its **audit event** and its
**exported runtime evidence** carry, and so that the canonical payload digest binds it.

G1a put the identity into `PolicyContext`. This slice moves it the rest of the way.

## Production path, traced before the change

```
ToolAuthorizationCoordinator                tramai-engine/.../tool/ToolAuthorizationCoordinator.kt:12
  (also ToolExposureCoordinator:17, ToolReinjectionCoordinator:39)
→ policyHelper.evaluate(context)            tramai-engine/.../PolicyEnforcementHelper.kt:39-44
     policyEngine.evaluate(context)  → PolicyDecision        (G1a identity already in context.attributes)
     auditEmitter.emit(enforcementPoint, context, decision)  ← the emitter receives the FULL context
→ AuditEnginePolicyDecisionAuditEmitter     tramai-security/.../audit/AuditEnginePolicyDecisionAuditEmitter.kt
→ AuditEngine.emit(AuditEmission)           tramai-security/.../audit/AuditEngine.kt:11-34
→ ToolPermissionRuntimeEvidenceExporter     tramai-security/.../evidence/ToolPermissionRuntimeEvidenceExporter.kt
→ RuntimeEvidenceRecord
```

Two places convert a policy context into audit evidence on this path, and both dropped the identity:

- `AuditEnginePolicyDecisionAuditEmitter.buildSafeMetadata()` filtered `context.attributes` to
  `ALLOWED_ATTRIBUTE_KEYS = {"cacheReuse", "fallbackReason"}` and prefixed survivors with `attr_`.
  The five reserved `identity.*` attributes never reached the `AuditEvent`.
- `BoundaryEvidenceRecorder.record()` (the G1a Spring AI boundary) hand-built its emission with only
  `toolName` and `enforcementPoint`, so the example boundary's own evidence was unattributed — even
  though `GovernedToolCallback` documents that "evaluation, refusal and evidence therefore all carry
  the same identity".

And the exporter never attributed at all: `toToolPermissionRuntimeEvidenceRecord()` called no
`RuntimeEvidenceAttribution.merge` and no `.validate`, its family allowlist would have dropped
`identity.*` anyway, and its canonical digest covered only eventType, decision, reasonCode, source and
metadata. The identity neither travelled nor bound.

## Boundaries modified

| File | Change |
|---|---|
| `tramai-security/.../audit/AuditEnginePolicyDecisionAuditEmitter.kt` | carry the five reserved `identity.*` keys **verbatim** (no `attr_` prefix), reserved **before** the attribute slot budget so a shortage cannot truncate a complete tuple into a partial one |
| `tramai-security/.../evidence/ToolPermissionRuntimeEvidenceExporter.kt` | `validate` → `merge` (overlay after the family allowlist, **before** the digest) → digest over the attributed payload; the canonical run id joins the canonical payload **for attributed records only** |
| `examples/spring-ai-authority-boundary/.../BoundaryOutcome.kt` | one `internal` translation `BoundaryContext.identityAttribution`, so evaluation and evidence cannot drift from each other |
| `examples/spring-ai-authority-boundary/.../BoundaryEvidenceRecorder.kt` | the recorded emission carries that identity |
| `examples/spring-ai-authority-boundary/.../GovernedToolCallback.kt` | uses the shared translation instead of its own private copy (net deletion) |

No new type, no new evaluator, no evidence-schema change, no database change, no CI change, no
baseline or suppression change, and no change to any enforcement decision.

## Invariants preserved and strengthened

- **One authoritative source.** The reserved `identity.*` keys in `PolicyContext.attributes` are the
  only identity the evidence path reads, and `RuntimeEvidenceAttribution` is the only definition of
  their names.
- **Atomic attribution.** Evidence is wholly attributed or not attributed at all: zero keys is legacy
  and stays valid; a partial tuple is corruption and is refused; a complete tuple without a
  non-blank canonical `workflowRunId` is refused. The exporter refuses to emit rather than downgrade.
- **The digest binds what the record shows.** The overlay precedes the digest computation, so a record
  cannot advertise a digest that does not cover the identity it displays.
- **Exfiltration allowlist intact.** Identity is overlaid *after* the family allowlist, so the
  allowlist keeps its purpose and is not widened. An unknown or near-miss key is still filtered.
- **Existing semantics unchanged.** No enforcement point, decision, reason code, refusal or prevention
  behaviour changed. Legacy (unattributed) evidence produces byte-identical digests to before.

The security suite drives the real `DefaultPolicyEngine`, the real
`AuditEnginePolicyDecisionAuditEmitter` through the real `AuditEngine`, and the production exporter,
with the identity taken from a typed `GovernedRunIdentity` through the production translation
`GovernedIdentityAttribution` — not pasted in from a literal. The boundary suite drives the real
`GovernedToolCallback`, inspects the audit event it recorded, and reads the exported record.

The pair of legacy/attributed assertions is the discriminating property: an implementation that
carries nothing passes the legacy case and fails the attributed case; one that attributes everything
passes the attributed case and fails the legacy case. Neither passes both by accident.

## Review corrections (first exact-head review)

The first review returned HOLD with two findings. Both are resolved here.

### Finding 1 (P1) — reserved identity values could be silently truncated

`buildSafeMetadata` carried the reserved keys through the generic `bounded(value)` helper, which
truncates at `MAX_VALUE_LENGTH` (256). **A claim in this slice was wrong and is withdrawn:** "identity
values are at most 128 characters because they come from typed identity objects, so the bound is a
no-op." That holds for the typed G1a boundary, but the *shared* emitter accepts any `PolicyContext`,
and `DefaultPolicyEngine.evaluate()` validates attribution presence and the canonical run id — **not
value lengths**. Two complete, otherwise identical contexts whose `identity.deploymentId` differs only
after the 256th character were therefore accepted, truncated to the same 256 characters, and exported
with identical identity metadata **and identical payload digests**. Two different evaluated identities
produced one indistinguishable evidence pair — a direct breach of this slice's central guarantee.

**Correction:** authoritative identity never passes through a lossy function. The reserved keys are
stored byte-for-byte and an overlength value **fails closed** with a message naming the key and the
bound. `bounded()` keeps its role for the non-identity metadata only. A value of exactly the bound is
still accepted and preserved.

Discriminator, in an isolated worktree with the fix reverted and nothing else changed: control
`tests=13 failures=0`; fix reverted `tests=13 failures=1` with
*"Expected an exception of class IllegalArgumentException to be thrown, but was completed
successfully"* — i.e. the overlength identity was silently accepted, which is the defect; restored
byte-identically, `tests=13 failures=0`. Transcript: `evidence/…/f1-discriminator.txt`.

### Finding 2 (P2) — no proof that attributed evidence survives bundling

The earlier tests established evaluator → audit → exporter carriage but never exercised a finalized
bundle. Added, through production classes only:

- `complete real tool-permission evidence is bundled across ALLOW, REQUIRE_APPROVAL, and DENY and survives
  intact` — real records for all three decision kinds, written by `RuntimeEvidenceBundleWriter` to
  `runtime-evidence/tool-permissions.jsonl`, then re-read and asserted field by field: every reserved
  identity key, the canonical `workflowRunId`, the decision kind and reason code, and both digests.
- `tampered attributed tool-permission evidence is detected by production contract verification` —
  four tamper cases (partial attribution, attribution without the canonical run id, an unallowlisted
  metadata key, and a corrupted `manifest.json`), each asserting the specific refusal, through both
  `RuntimeEvidenceContractValidator` and the writer.

**Stated limitation, not a claim:** the repository has no production JVM verifier that performs
cryptographic SHA-256 integrity checking of an on-disk `tool-permissions.jsonl` against `manifest.json`.
Within the JVM pipeline, integrity operates through the contract validator and the writer. This is
asserted in the test's KDoc rather than papered over with an invented verifier.

### A third gap found while correcting — FIXED in this PR

`examples/sovereign-lab/verify-evidence-bundle.sh` — the documented reviewer-facing bundle verifier —
mirrored the family allowlists by hand. Its `tool.permission` list (L220-221) held only `toolName,
enforcementPoint, riskLevel, classification, classificationSource`, and L452-461 rejected any
non-allowlisted key, so **a valid G1b-attributed record failed the verifier** even though the JVM
`RuntimeEvidenceContractValidator` accepted it. That is a contract incompatibility between the evidence
producer and the documented reviewer path, not merely a missing test: the reviewer guide states a failed
verification means the bundle is not review-ready. It was first reported rather than fixed, because the
review had bounded the correction to identity fidelity and the missing integration evidence; the second
review then authorised this narrow correction, on the grounds that G1b's evidence must actually be
reviewable.

Reproduced before fixing, at the artifact level and independent of any test. The only variable is
attribution:

| fixture | reviewer verifier |
|---|---|
| five identity keys + `workflowRunId` | `metadata key 'identity.workloadId' is not allowlisted for tool.permission` → exit 1 |
| identical record, identity and run id stripped, re-finalized | `Evidence bundle verified:` → exit 0 |

**Correction** (`+27/−4`, nothing else in the file touched): the five reserved keys are defined once as
`GOVERNED_IDENTITY_KEYS`; the four family allowlists are left exactly as they were and the identity keys
are composed on top for **every** family, mirroring `RuntimeEvidenceContractValidator`'s
`familyAllowedKeys + RuntimeEvidenceAttribution.metadataKeys`; and attribution is then enforced
atomically — zero identity keys stays legacy evidence and keeps verifying, a partial tuple is refused
naming the missing keys, and all five require a non-blank `workflowRunId`.

**Acceptance test** in the established real-bundle path
(`RuntimeEvidenceBundleIntegrationTest`, `tramai-spring-boot-starter-sovereign-ops`) drives the real
pipeline: production-exported attributed records, then `finalize-evidence-bundle.sh`, then
`verify-evidence-bundle.sh`, asserting `Evidence bundle verified:` — not merely a zero exit. Plus an
on-disk tamper case applied **after** finalization, asserting `sha256 mismatch for
runtime-evidence/tool-permissions.jsonl`, and three negative controls each re-finalized first so the
failure can only be the metadata rule. Tests assert reasons, never just non-zero exits, and fail loudly
if the scripts are absent.

**Evidence.** Artifact-level, cache-free and Gradle-free — nine checks, all as intended: attributed and
legacy records verify; partial identity, missing run id, blank run id and an unknown metadata key each
refuse with their specific message; with **only** this fix reverted the attributed record is refused
while the legacy control still verifies, proving the fix is load-bearing and attribution-scoped.

| corrected tree | PROVEN | boundary suite 7/7, security 13/13 |

## Explicit non-claims

1. **Authenticity is not established.** The reserved keys are *carried*, not re-derived and not
   cryptographically bound. `PolicyContext` is a public type, so any caller that can build one can set
   those keys; this slice cannot distinguish a boundary-populated identity from a caller-populated
   one. The evidence attests **the identity the decision was evaluated under**, not that the identity
   is authentic. Establishing authenticity is workload registration / workload authenticity (G2) and
   is explicitly outside this slice.
2. **The run id is bound in the payload digest for attributed records only.** The requirement was
   determined experimentally, not assumed: a test that varies only the canonical run id, holding the
   five deployment fields and the decision identical, was added first and **failed** against the
   pre-change canonicalization (`expected: not equal but was: sha256:...`) — the payload digest did
   not bind the run id. It was then made to pass by adding the run id to the canonical payload of an
   attributed record, with a matched control asserting that a **legacy** record's payload digest is
   unchanged by the run id. Note the weaker binding that existed before and still exists:
   `subjectDigest` is `sha256(auditStreamId)`, and `auditStreamId` equals the run id only because
   `DefaultAuditStreamIdResolver` returns it — a deployment installing its own resolver would have
   left the run id bound by nothing, which is why the payload digest now binds it directly.
3. **The `governance.decision` family has the same characteristic and is out of scope.** Its
   `payloadDigest` (`GovernanceDecisionEvidence.payloadDigest`) does not include `identity.runId`
   either. Extending it would re-digest that family's existing evidence, which this slice must not
   do, and the governance path is not the tool-permission path this milestone owns. Reported, not
   fixed.
4. **Blank identity values still pass validation.** The shared validator checks key *presence*, not
   value meaning, so a complete tuple of blank values is accepted. This is pre-existing behaviour
   pinned by `GovernedIdentityValidationTest` ("presence only, documented not endorsed"); G1b inherits
   it and does not change it.
5. **`apiCheck` for `examples:spring-ai-authority-boundary` is red before and after this change** —
   the module has never had a committed API dump. The `internal` visibility chose above keeps that
   module's public surface unchanged regardless, which is what the no-public-API-change criterion
   actually requires. Generating the missing dump would be adding an API baseline and is out of scope.
6. **The evidence does not prove where the identity came from in the example either.** The example's
   guarantee is a property of its wiring (one `BoundaryContext` per boundary, held in place by
   `EvidenceIntegrityTest`), not of the record.
