P1 — `accountedPositions` did not independently prove coverage   FIXED
--------------------------------------------------------------------------------
The finding was correct and was the strongest one in the round: the account was
`events.size.toLong()`, and the attested range already requires `events.size == head`. So
`accountedPositions == span` was true by construction whenever a range was attested, and the
completeness contract was comparing a number against itself. The owner's counterexample — a
`DecisionFactRead` whose coverage names a range it never classified — was reachable through the
internal contract for exactly that reason.

Correction: the classification is now an exhaustive per-event pass. `EventOutcome` names the four
outcomes (decision record, recognised non-decision, missing record, unclassified), `ClassifiedEvent`
carries the outcome and the record, and `records`, both position sets and `accountedPositions` are
all derived from those outcomes. An event the pass never reaches shrinks the account, which withholds
`COMPLETE` instead of hiding the omission. No mutable accumulator is introduced: one `map` followed by
linear projections.

Discriminator and decisive experiment (battery runs at the corrected head):

  K8  the classification pass silently drops every recognised non-decision event
      APPLIED -> KILLED by `a mixed stream keeps its verified range and accounts for every event`
      and `a mixed stream reports a complete record set over its verified range`
      (records still [1, 3], account 2 of 3, so COMPLETE is withheld)

  M8  the SAME omission, with the account restored to the input size - the rejected derivation
      APPLIED -> SURVIVED, 207 tests, 0 failures

  M8 is the point of the experiment rather than an escape: the identical classification defect is
  invisible under the derivation the owner rejected and detected under the current one. That is the
  evidence that the guard is load-bearing rather than decorative.

P2 — an unknown enforcement point was reported as a proven gap   FIXED
--------------------------------------------------------------------------------
Also correct: `isDecisionOutcome` accepted any event carrying a decision token, so
`enforcementPoint = UNKNOWN_BOUNDARY, decision = ALLOW` was placed in
`unrecordedDecisionPositions` and could produce `GAPS_PRESENT`. The source cannot establish that an
unrecognised boundary was supposed to produce a record.

Correction: `isMissingRecord` requires the boundary to be one a decision family owns
(`POLICY_ENFORCEMENT_POINTS` or `TOOL_ENFORCEMENT_POINTS`) as well as the token. `GAPS_PRESENT` now
means "a record that should exist does not" and not "something decision-shaped went past".

- `an unrecognised enforcement point is not reclassified as a policy decision` now asserts the event
  is unclassified (`unclassifiedPositions = {1}`, `unrecordedDecisionPositions` empty) with the range
  still attested.
- `a tool enforcement event without a tool name becomes no record at all` carries the positive case
  `GAPS_PRESENT` is reserved for: a recognised tool boundary, a decision token, no record buildable
  from it. It now asserts `unrecordedDecisionPositions = {1}`.
- Battery K5 (`isMissingRecord` -> false) APPLIED -> KILLED by that test.

P2 — quadratic classification cost   FIXED
--------------------------------------------------------------------------------
Correct, and worse than a style point: `records = records + record` and both `+ position` set
rebuilds ran per event, which is O(n^2) against a bounded read of up to `maxEventsPerRead`
events. Replaced by one linear map plus linear projections; a review thread on the same lines is
resolved with this change.

--------------------------------------------------------------------------------

  implied as a stronger binding than exists.
