K6 — SURVIVOR, WITH ITS MECHANISM ESTABLISHED
--------------------------------------------------------------------------------
The mutation removes `events.size == headBefore.sequenceNumber` from `verifiedRange`. Every test
still passes, which is a survivor and not a kill.

Mechanism: the condition is redundant over the same read. A read that stops short of the head has
`last.sequenceNumber != headBefore.sequenceNumber`, which the endpoint anchor already refuses; a read
with a hole in the middle cannot be produced by a hash-chained store at all, because
`AuditChainVerifier.verifyChainPosition` refuses the broken linkage first; and a read missing its
first event fails the `first == FIRST_SOURCE_POSITION` condition.

Evidence for that rather than an argument from the code alone: a fixture was added for the case the
mutation targets — a coherent chain stopping one event short of the reported head, with the page after
the drop answered empty (`a read that stops short of the head attests no range`, asserting records
[1, 2] and no verified range). It passes **with K6 applied**, so the endpoint anchor is what refuses
that read, and the count repeats a refusal that is already made. Recorded as a survivor with this
mechanism; not counted as a kill, and not removed from the code, because it is the guard that states
the contiguity requirement directly.

The report also names what a kill would require: a store that can return a non-contiguous list with a
matching endpoint and a verifying chain, which the chain verifier makes impossible for this SPI.
