FINDING P1-A — cross-run events were filtered, not refused
--------------------------------------------------------------------------------
Was: `decisionKindOf` returned null for `event.workflowRunId != requestedRun`, so another run's
event was dropped before the c1 reader's own cross-run refusal could see it, and the read could
still publish an attested stream range.
Now: attribution is enforced over the whole verified read and fails closed —
`events.firstOrNull { it.workflowRunId != workflowRunId }` raises
`AuditDecisionAttributionException` naming the stream, the requested run and the offending
position. Multi-run streams are unsupported by this source; a shared-stream mode would be a
separate mode with its own attribution and completeness semantics, not a silent filter.
`decisionKindOf` no longer carries the run check, because the read cannot reach it with a foreign
event.
Discriminator: `a foreign-run event in a run-named stream refuses the read instead of being
dropped` — three events in the requested stream, one of them run-2's, and the read fails rather
than returning the two facts it owns.

FINDING P1-B — the attested range was not anchored to the observed stream head
--------------------------------------------------------------------------------
Was: attestation compared positions only (first == 1, count == head position, head unchanged),
while `AuditChainVerifier` proves only that the returned list is internally consistent. A source
answering with a different but coherent chain of the same length was therefore attestable.
Now: `attestedRange` additionally requires every read event to carry the requested stream id, the
last event's hash to equal the observed head's hash, and the head's identity (position AND hash)
to be unchanged across the read. The empty case stays unattested (`lastOrNull` is null).
Discriminators:
  `an internally valid chain from another stream is not attested as this stream's range`
  `a head that is not the event last read does not attest the range`
