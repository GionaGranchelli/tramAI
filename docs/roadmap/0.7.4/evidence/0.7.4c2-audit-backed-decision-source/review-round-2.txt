FINDING P1-A — a wrong-stream response still produced governance facts
--------------------------------------------------------------------------------
Was: the stream-identity check only withheld the attested range, so a page read answered from
another stream still became POLICY_AUTHORIZATION_RECORD facts with unknown completeness. The
adversarial test asserted that behaviour, which is what the review objected to.
Now: a foreign stream id is an integrity failure. `AuditDecisionStreamMismatchException` names the
requested stream and the offending event's stream and position, and the read is refused. The
per-event stream check inside `attestedRange` is removed, because the refusal supersedes it.
Discriminator: `a read answered from another stream is refused, not narrowed` (rewritten from the
former "is not attested as this stream's range", whose assertions accepted the records).

FINDING P1-B — non-decision audit events manufactured GAPS_PRESENT
--------------------------------------------------------------------------------
Was: a verified stream [policy ALLOW, DLP REDACTED, policy DENY] produced projected positions
[1, 3] against an attested range 1..3, and `GovernanceFactClassification.completenessOf` read that
as a gap. The stream had none.
Now: a range is attested only when every verified event became a fact (`projectedCount==
events.size`). A filtered read reports no range, and coverage null makes the folded completeness
UNKNOWN. This is the conservative option the review allowed: the frozen completeness contract is
untouched, so its semantics for a range stay exactly as qualified in 0.7.4c1.
Consequence, stated because it is a real loss: a stream that carries any non-decision event can
never report COMPLETE through this source. Expressing "the stream was read in full" separately from
"these decisions were projected" needs a contract change, which is a different slice.
Expectation update in `an unrecognised enforcement point is not reclassified as a policy decision`:
it asserted `assertedRange == 1..1` for a single filtered event, which encoded the old rule. It now
asserts no range, with the reason in place. The family-partition guarantee it names is unchanged and
still discriminated (M3).
Discriminators: `a verified stream with non-decision events does not manufacture gaps` (adapter),
and `an interleaved non-decision event does not report a gap` (through the projection: policy
completeness UNKNOWN, not GAPS_PRESENT, latest at source position 3).

FINDING P2 — maxEventsPerRead could be exceeded
--------------------------------------------------------------------------------
Was: the loop asked for a full `pageSize` while fewer slots remained, so pageSize 2 with a cap of 3
read four events and could attest a range of 1..4 over a three-event cap.
Now: each page asks for `minOf(pageSize, maxEventsPerRead - events.size)`.
Discriminator: `a bounded read never exceeds maxEventsPerRead` — a non-divisible boundary (4 events,
page 2, cap 3) asserting records [1, 2, 3] and no range.
