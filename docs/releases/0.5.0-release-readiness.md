# 0.5.0 Release Readiness

## Release Theme

**Governed AI workflows for the JVM**

TramAI 0.5.0 represents the post-sovereignty maturation of TramAI as a governed AI workflow runtime. This release focuses on API stability boundaries, structured output hardening, workflow ergonomics, approval gates, runtime evidence export, tool governance, and product adoption documentation.

## Upgrade Notes from 0.4.0

### JavaBean schema behavior

Java DTOs with conventional bean accessors now contribute real properties, required fields, nested types, collection item schemas, and TramAI field annotations to generated structured-output contracts (PR #198). Previously, Java POJO properties were invisible to Kotlin reflection, resulting in empty schemas. Existing Kotlin schema behavior is unchanged. Java records and arbitrary immutable POJOs remain out of scope.

### Structured-output validation changes

Structured-output validation now includes `@AIRange` and `@AIMinItems` annotation processing (PR #169). Repair feedback has been hardened with regression tests proving parse/validation failures produce useful diagnostic messages (PR #171).

### Tool-permissions.jsonl in bundles

The sovereign evidence bundle now includes a `tool-permissions.jsonl` file in `runtime-evidence/` when tool permission runtime evidence is exported (PR #200). This file is structurally validated by the bundle verifier for required fields (`toolName`), valid enforcement points, bounded risk levels, and code-shaped reason codes.

### Tool evidence moving to dedicated family

Tool enforcement events (`BEFORE_TOOL_EXPOSURE`, `BEFORE_TOOL_EXECUTION`, `BEFORE_TOOL_RESULT_REINJECTION`) are now partitioned into a dedicated `tool.permission` evidence family, separate from generic `policy.decision` (PR #200). The policy decision exporter now excludes tool events as a regression guard.

### New examples

- `examples/governed-workflow`: deterministic claim triage with policy and approval gates (PR #174)
- `examples/approval-resume`: durable approval suspension and resume with embedded PostgreSQL (PR #179)
- `examples/tool-governance`: governed tool usage example

### Preview API changes

Several APIs remain in Preview status and may evolve in future releases. These include the approval control plane REST endpoints, reviewer UI, runtime evidence exporters, and tool governance APIs. See the [Workflow API stability boundary](../workflow-api-stability-boundary.md) for the current classification.

## Publication Boundary

This PR prepares the release commit for TramAI 0.5.0. It does **not**:

- Publish to Maven Central or Sonatype
- Create a tag or GitHub release
- Require signing keys
- Freeze APIs

**Post-merge sequence:**

1. Merge this release preparation PR to `master`
2. Create a `v0.5.0` tag on the merge commit
3. Push the tag to trigger the `Publish` workflow
4. The workflow performs a remote-release publish to Maven Central
5. Central Portal requires operator validation before artifacts are published
6. After Central Portal acceptance, confirm the published coordinates externally

## Non-claims

TramAI 0.5.0 does **not**:

- Certify production readiness for every deployment configuration
- Provide legal compliance, regulatory compliance, or EU AI Act conformity
- Guarantee security certification (SOC2, ISO 27001)
- Validate evidence truth — only structural tamper-evidence is verified
- Provide benchmark guarantees — benchmarks are diagnostic only
- Replace an audit or compliance review
- Provide a governed MCP connector
- Provide key rotation
