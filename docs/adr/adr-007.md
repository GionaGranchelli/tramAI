# ADR-007: Resolve Providers from Model Names with Explicit Override Support

- Status: accepted
- Date: 2026-04-17

## Context

Aurora needs a practical way to route operations to providers without forcing the consumer to specify both provider and model on every method. The design proposes model-prefix routing while also acknowledging that explicit provider selection should remain available.

## Decision

Aurora will resolve providers primarily from model naming conventions and allow explicit provider override where needed.

Examples:

- `claude-*` routes to Anthropic
- `gpt-*`, `o1-*`, and `o3-*` route to OpenAI
- local model families such as `llama*`, `mistral*`, and `gemma*` route to Ollama
- `@Operation(provider = "...")` can override automatic routing

## Consequences

Positive:

- low-friction default behavior
- simple mental model for consumers
- explicit escape hatch when defaults are not enough

Negative:

- provider routing depends on naming conventions staying stable
- registry design may need to evolve as provider catalogs expand

## Follow-Up

If model naming conventions become too brittle, create a replacement ADR for explicit model registration or richer provider registry rules.
