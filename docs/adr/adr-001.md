# ADR-001: Use Annotated Interface Methods as the Primary AI Abstraction

- Status: accepted
- Date: 2026-04-17

## Context

Aurora is intended to feel idiomatic to Kotlin and Java backend engineers. The design rejects chain-oriented and agent-oriented APIs as the primary programming model. The product goal is one annotated interface, typed parameters, typed results, and minimal application-facing complexity.

## Decision

Aurora will use annotated interface methods as the core abstraction:

- interfaces are marked with `@AiService`
- methods are marked with `@Operation`
- method signatures define inputs and output behavior
- consumers do not write implementations
- Aurora generates implementations at runtime

## Consequences

Positive:

- aligns with JVM backend engineering conventions
- keeps business code focused on typed contracts
- gives a single primary abstraction instead of a broad surface area

Negative:

- some advanced AI patterns become harder to express in v1
- proxy generation and reflection become central implementation concerns
