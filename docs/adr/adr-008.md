# ADR-008: Build Kotlin-Native APIs with Java-Friendly Entry Points

- Status: accepted
- Date: 2026-04-17

## Context

Aurora is written in Kotlin and should feel native in Kotlin applications, but the product target includes Java backend engineers. The design therefore requires coroutine-native Kotlin APIs and explicit Java-callable access patterns.

## Decision

Aurora will use Kotlin-native APIs internally and externally where appropriate, while providing Java-friendly entry points for core workflows.

This includes:

- coroutine-native provider contracts
- Kotlin DSL configuration for standalone use
- Java builder entry points
- blocking wrappers for suspend-based operations

## Consequences

Positive:

- strong Kotlin ergonomics without excluding Java users
- one implementation model for provider I/O
- clear interoperability story for mixed JVM teams

Negative:

- dual API expectations increase documentation and testing needs
- blocking wrappers must be designed carefully to avoid surprising threading behavior
