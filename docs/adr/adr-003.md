# ADR-003: Make Structured Output the Default Non-String Contract

- Status: accepted
- Date: 2026-04-17

## Context

Tramai is positioned as structured-first. The roadmap and design both treat typed outputs as a primary value proposition, not an optional feature. Raw `String` output remains valid, but typed return values should automatically use schema-guided parsing and validation behavior.

## Decision

Tramai will interpret method return types as follows:

- `String`: raw model output
- `Unit`: no parsed result
- data classes and POJOs: structured output with schema generation, parsing, validation, and retry

Structured output failures will not be silently ignored. They will enter the structured retry flow and eventually throw a typed exception if recovery fails.

## Consequences

Positive:

- reinforces Tramai's core differentiation
- makes typed interfaces meaningful in practice
- encourages reliable application integration instead of ad hoc text parsing

Negative:

- structured output introduces more runtime machinery
- model compatibility and prompt discipline matter more
- exception handling becomes part of normal consumer expectations
