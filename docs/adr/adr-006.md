# ADR-006: Enable OpenTelemetry Observability Automatically When Present

- Status: accepted
- Date: 2026-04-17

## Context

Observability is a core product claim, not an optional add-on. At the same time, Aurora should impose no mandatory observability dependency on users who do not use OpenTelemetry.

## Decision

Aurora will auto-enable OpenTelemetry-based observability when the required APIs are on the classpath and otherwise use a no-op path.

The observability layer will:

- wrap provider calls in spans
- emit GenAI semantic convention attributes
- record structured parse failures as span events
- avoid breaking standalone use when OpenTelemetry is absent

## Consequences

Positive:

- strong default observability story
- minimal adoption friction in instrumented systems
- no hard dependency for users who do not need tracing

Negative:

- classpath detection and optional integration must be implemented carefully
- feature parity between instrumented and non-instrumented paths needs testing
