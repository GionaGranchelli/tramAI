# ADR-002: Start with Runtime Proxy Generation Using JDK Dynamic Proxy

- Status: accepted
- Date: 2026-04-17

## Context

The design compares compile-time generation with runtime proxying. v1 needs a direct path to a working library without introducing processor complexity too early. Runtime generation is sufficient for interface-based contracts and fits the initial scope.

## Decision

Tramai v1 will generate service implementations at runtime using JDK dynamic proxies.

Compile-time generation via KSP remains a possible future evolution if startup cost, diagnostics, or native image support become important enough to justify the extra complexity.

## Consequences

Positive:

- faster path to a working v1
- simpler build integration for early users
- enough capability for interface-only service contracts

Negative:

- weaker compile-time feedback than generated code
- more reflection-related concerns for native images
- some future optimizations are deferred

## Follow-Up

If native image support or startup cost becomes a product priority, create a new ADR to evaluate KSP-based generation as a replacement or alternate backend.
