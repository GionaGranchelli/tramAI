# ADR-004: Use Custom Jackson-Based Schema Generation

- Status: accepted
- Date: 2026-04-17

## Context

The design explicitly calls out the need for schema generation that understands `@AiDescription`, range and collection constraints, and Kotlin nullability semantics. Off-the-shelf schema generation is not sufficient for the level of control Tramai wants over structured output behavior.

## Decision

Tramai will use a custom Jackson-based schema generation pipeline for structured outputs.

The generator must support:

- Kotlin data classes and Java POJOs
- Kotlin nullability mapped to required and optional schema fields
- Tramai-specific annotations such as `@AiDescription`, `@AiRange`, and `@AiMinItems`
- schema caching per operation

## Consequences

Positive:

- better schema quality for model guidance
- explicit support for Tramai-specific annotations
- tighter control over consistency and future evolution

Negative:

- more code to maintain than a library-default generator
- schema correctness becomes Tramai's responsibility
