# ADR-017: Keep Orchestration Typed, Workflow-Owned, and Optional Above `tramai-engine`

- Status: accepted
- Date: 2026-04-20

## Context

Tramai now has the core pieces needed to power richer AI workflows: typed `@AiService` contracts, structured outputs, tool calling, streaming, retries, fallback routing, token budgets, caching, and observability.

That naturally raises the next design question: should Tramai support orchestration or coordination across multiple AI-backed services?

The opportunity is real. Backend teams often need workflows like planning, specialist fan-out, review, and finalization. At the same time, a naïve multi-agent design would pull Tramai toward generic agent frameworks, hidden memory, and loosely typed chat loops, which would undermine the project's current strengths.

## Decision

Tramai orchestration, if added, will be:

- typed
- workflow-owned
- optional at the module level
- layered above `tramai-engine`

The initial design boundary is:

- orchestration composes existing `@AiService` methods and local application steps into explicit workflows
- `tramai-engine` remains the owner of single-call execution, retries, budgets, caching, tools, and provider routing
- orchestration coordinates steps, branches, merges, and stop conditions, but does not redefine the provider execution contract
- orchestration must not begin as free-form autonomous agent collaboration or hidden long-lived memory

## Consequences

Positive:

- preserves Tramai's identity as a typed backend workflow library rather than a generic agent runtime
- reuses the existing engine's resilience, observability, and provider portability
- makes multi-step AI workflows auditable and testable

Negative:

- orchestration adds a second abstraction layer that must stay smaller and clearer than typical agent frameworks
- some users expecting emergent multi-agent collaboration may find the design intentionally constrained

## Implementation Guidance

- Prefer a dedicated module such as `tramai-orchestration`.
- Make workflow state and step handoffs typed by default.
- Keep rounds, fan-out, merge behavior, and stop policies explicit.
- Treat free-form agent-to-agent conversation as a later and higher-risk design area, not the first milestone.
