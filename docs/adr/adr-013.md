# ADR-013: Start Streaming with Raw Text and a Dedicated Streaming Contract

- Status: accepted
- Date: 2026-04-18

## Context

Tramai needs streaming support, but the first streaming milestone can easily become too broad if it tries to handle raw text, structured partials, tool events, provider-native quirks, and Java wrappers all at once.

The project already has a clear request/response execution model centered on annotated interface methods. Streaming should extend that model without forcing a premature redesign of structured output or tool calling.

## Decision

Tramai will start streaming with a raw-text-first design and a dedicated streaming contract.

The initial streaming boundary is:

- streaming is a first-class execution path, not an internal implementation trick
- the first milestone covers raw text streaming only
- streamed structured output is deferred
- the engine owns streaming orchestration and cancellation
- providers adapt their native streaming transports into Tramai's shared streaming contract

## Consequences

Positive:

- keeps the first streaming milestone small enough to implement correctly
- preserves a clean path for cancellation and observability
- avoids overpromising streamed structured output before the validation story is ready

Negative:

- typed structured streaming remains unavailable in the first milestone
- Java-facing streaming ergonomics may lag the initial Kotlin-first design

## Implementation Guidance

- Do not define the first streaming milestone as "all existing operations, but incremental."
- Keep non-streaming paths unchanged.
- Prefer a streaming contract that can grow later rather than hard-coding everything to raw `String` chunks internally.
