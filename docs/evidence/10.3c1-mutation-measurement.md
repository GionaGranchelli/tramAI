# 10.3c1 Mutation Measurement Evidence

First real targeted PITest measurement of the seven declared critical behavior
families. Evidence for the 10.3c2 survivor-ratchet design: population size,
cost, and determinism.

## Pinned mutation semantics (C1)

| Component | Value |
|---|---|
| gradle-pitest-plugin | 1.19.0 |
| PIT engine (`org.pitest:pitest`) | 1.22.1 (`DEFAULT_PITEST_VERSION` of the plugin, verified from the jar) |
| pitest-junit5-plugin | 1.2.1 (required for JUnit 5 projects) |
| Mutator set | explicit expansion of PIT `DEFAULTS`: `CONDITIONALS_BOUNDARY, INCREMENTS, INVERT_NEGS, MATH, NEGATE_CONDITIONALS, TRUE_RETURNS, FALSE_RETURNS, PRIMITIVE_RETURNS, EMPTY_RETURNS, NULL_RETURNS, VOID_METHOD_CALLS` |
| Timeout | `timeoutConstInMillis = 4000`, `timeoutFactor = 1.25` — PIT's documented defaults pinned explicitly (C1); a future plugin upgrade cannot silently change timeout semantics |
| Identity schema | v2 — module, className, method, methodDescription (JVM descriptor), mutator, description, block, index; SHA-256; excludes line/paths |
| Outcome model | canonical `KILLED | NON_KILLED` (ratchet authority) + raw PIT `status` (diagnostic); canonicalization is exhaustive — `NON_VIABLE`, `MEMORY_ERROR`, `RUN_ERROR`, `REMOVED`, `NOT_STARTED` or any unknown status fails the measurement (fail closed, never silently NON_KILLED) |
| Baseline schema | `config/quality/mutation-baseline.json`, schemaVersion 1, identitySchemaVersion 2 |

> `RETURN_VALS` is a mutator **group**, not a mutator name — the engine rejects
> it (`Mutator or group RETURN_VALS is unknown`). Pinning the expanded list
> (the 5 `*_RETURNS` + 6 others) is what keeps a future engine's group
> redefinition from silently changing the population.

## Determinism (C7)

C7 authority definition (user doctrine): the committed mutation authority must
be deterministic at the **identity + family + kill-state** level. Exact PIT
execution statuses remain diagnostic evidence.

- same analyzer semantics — required
- same family set — required
- same mutant identity set — required
- same family memberships — required
- same `KILLED | NON_KILLED` outcome — required
- same authority counts (`killed = N`, `nonKilled = M`) — required
- raw `SURVIVED/NO_COVERAGE/TIMED_OUT` distribution — recorded, not authority
  (may legitimately differ across a SURVIVED↔TIMED_OUT flip)

Allowed: `SURVIVED ↔ TIMED_OUT` flip when canonical outcome stays `NON_KILLED`.
Absolute C7 failure: any `KILLED ↔ NON_KILLED` flip, any identity/status
collision, any unknown or tool-failure status.

### Initial finding (pre-model-fix)

The first deterministic pair (before the canonical model) exposed exactly the
race the model needed to absorb: 2372 identities fully stable, 0 collisions,
aggregate counts identical — but 2 mutants flipped `TIMED_OUT ↔ SURVIVED`
between identical runs:

- `approval/ResumeOperationRegistry.createKey` `VoidMethodCallMutator`
- `routing/ModelRegistryEnforcer.authorize` `VoidMethodCallMutator`

Both are non-killed in both runs; the flip is a PIT minion scheduler race at
the timeout boundary, not a behavioral change. Response: made
`KILLED | NON_KILLED` the canonical ratchet state, preserving raw status as
diagnosis. The 20s-timeout experiment was rejected (cost 23m48s on approval
for no authority gain — SURVIVED↔TIMED_OUT is the same NON_KILLED state);
timeout is pinned to PIT's documented 4000ms/1.25 instead.

## Cost observations for 10.3d/10.5 scheduling

- Total PIT wall ≈ **60 min** for 2372 mutants on 2 threads.
- Dominant families: policy (22 min), retry (11.7 min), routing (10 min),
  tools (11.2 min) — low mutant counts but high per-mutant cost (few tests /
  slow coverage setup), vs evidence/approval with hundreds of mutants in
  ~2-3 min.
- A nightly/release mutation lane is the natural 10.5 destination; a
  per-PR mutation gate at this cost is not viable without targeted
  changed-file selection.

## Dormant machinery repairs (pre-requisite)

The probe had never run on master; three stacked bugs fixed:

1. `startParameter.projectProperties` is empty on included builds → init
   script threw `Unknown or missing tramaiMutationFamily` on `build-logic`.
   Fix: `if (gradle.parent != null) return` at top of init script.
2. `PitestPlugin` defers extension creation until the Java plugin is present
   (`plugins.withType(JavaPlugin)`); `extensions.configure` in init scripts
   resolves its delegate to the build, not the extension. Fix: configure in
   `gradle.projectsEvaluated` via direct extension property access.
3. JUnit 5 projects fail without `org.pitest:pitest-junit5-plugin:1.2.1` on
   the `pitest` configuration (`JUnit 5 is on the classpath but the pitest
   junit 5 plugin is not installed`).
