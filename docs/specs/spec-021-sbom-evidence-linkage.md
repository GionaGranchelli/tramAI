# SPEC-021: CycloneDX SBOM Generation and Evidence Linkage

**Status:** implemented (PR #33)
**PR:** #33
**Branch:** feat/sbom-evidence-linkage

## Problem Statement

PR #32 (sovereign evidence pack) captures deployment configuration, artifact verification receipts, zero-egress probe results, and audit-chain status in a deterministic JSON artifact. However, it does **not** capture the supply-chain identity — the exact set of third-party dependencies and their versions shipped with each TramAI release.

Without supply-chain evidence, an auditor cannot:

- Verify that a deployment uses only known dependencies
- Correlate dependency CVEs against a specific deployed version
- Trace the exact set of libraries shipped in a build artifact

This spec defines **CycloneDX SBOM generation** and **supply-chain evidence linkage** into the existing Sovereign Evidence Pack.

## Scope

Implement:

1. CycloneDX SBOM generation via the `org.cyclonedx.bom` Gradle plugin (v3.2.4)
2. Aggregate BOM covering all subproject dependencies
3. SHA-256 digest file generated alongside the SBOM JSON
4. `SupplyChainEvidenceV1` DTO for evidence-pack linkage
5. Validation and sanitization in `SovereignEvidencePackGenerator`
6. Integration with `examples/sovereign-offline-verification` — optional `--sbom-path=` and `--sbom-digest-path=` arguments
7. CI pipeline steps for SBOM and digest generation
8. Unit and integration tests
9. Documentation (SPEC-021, task doc, module docs)

## SupplyChainEvidenceV1 DTO

```kotlin
data class SupplyChainEvidenceV1(
    val schemaVersion: Int = 1,
    val sbomFormat: String,
    val sbomSpecVersion: String,
    val sbomFileName: String,
    val sbomSha256: String,
    val generatedBy: String,
)
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `schemaVersion` | Int | Schema version (currently 1) |
| `sbomFormat` | String | The SBOM format standard (e.g. "CycloneDX") |
| `sbomSpecVersion` | String | The SBOM specification version (e.g. "1.6") |
| `sbomFileName` | String | The SBOM file name (no path components — rejected by sanitizer if present) |
| `sbomSha256` | String | SHA-256 digest in `sha256:<hex>` format (must match `^sha256:[a-fA-F0-9]{64}$`) |
| `generatedBy` | String | The tool that produced the SBOM (e.g. "CycloneDX Gradle Plugin 3.2.4") |

## SBOM Artifact Path

- **JSON:** `build/supply-chain/sbom/tramai-cyclonedx-sbom.json`
- **Digest:** `build/supply-chain/sbom/tramai-cyclonedx-sbom.sha256`
- **Format:** CycloneDX JSON (schema v1.6)
- **Coverage:** All subproject runtime classpath dependencies (aggregate)

## Digest File Format

The digest file contains exactly one line: `sha256:<64-hex-characters>`

Generated by the `prepareCycloneDxBom` Gradle task which runs `java.security.MessageDigest` over the SBOM JSON file bytes and writes the result.

## Security Invariants

- `sbomSha256` must match `^sha256:[a-fA-F0-9]{64}$` — validated in `SovereignEvidencePackGenerator`
- `sbomFormat`, `sbomSpecVersion`, `sbomFileName`, and `generatedBy` are sanitized through `EvidenceSafeString` (rejects path prefixes, secrets-adjacent terms, control characters)
- `sbomFileName` must not contain path separators (`/` or `\`) or drive letters — if it does, the generator throws `IllegalArgumentException("evidence-unsafe-identifier")`
- `sbomSha256` is **not** passed through `EvidenceSafeString` (hex digests may coincidentally contain substrings like "token") — instead validated via the regex above

## Non-Goals

- Dependency vulnerability scanning
- SLSA provenance attestation
- Image signing
- Runtime dependency verification
- Periodic SBOM regeneration
- Full SPDX format support (CycloneDX only for this PR)

## Residual Risks

| Risk | Mitigation |
|------|------------|
| SBOM contains stale dependency data | Generated at build time; consumers verify against digest |
| Digest file tampered | Digest is validated and sanitized before writing into evidence pack |
| SBOM grows large for large dependency trees | Only digest (64 hex chars) stored in evidence pack — SBOM JSON uploaded as separate CI artifact |
